# Caught Up — stack, cost and scaling

Caught Up is a static Next.js publication generated by GitHub Actions. Git and
MDX are canonical; Vercel serves the materialized reader output. Anthropic calls
and optional image generation happen only during editorial workflows.

## What scales with readership

Reader growth increases only static CDN transfer. It does not add database,
server-rendering, queue or model cost. The current architecture can serve the
first thousands of readers without a read-path redesign; the relevant hosting
plan and bandwidth limits still need normal operator monitoring.

## What scales with publishing

- Daily and weekly model cost scales with candidate context, output tokens,
  language variants, regeneration attempts and cadence.
- Illustrations cost only when a paid provider is selected; `none` is the
  committed default.
- Embeddings and model-written promotion are optional and disabled without an
  explicit key/toggle.
- Newsletter and social artifacts are deterministic files. Creating them has no
  provider fee; sending may introduce a separate provider cost.
- OwnDashboard callback traffic is optional and does not sit in the read path.

Actual Anthropic usage is recorded per stage and priced centrally by the
versioned registry in `lib/telemetry/pricing.ts`. Missing usage or unknown model
pricing is `unavailable`, never zero. `config/editorial.yml` supplies per-run and
monthly warning/hard-budget fields; the pipeline can enforce per-run hard limits
from committed configuration, while monthly aggregation requires the external
telemetry store described in `docs/OWNDASHBOARD_INTEGRATION.md`.

## Likely first constraints

The first operational constraints are generation quality, provider rate limits,
GitHub Actions duration and commercial hosting terms—not public read capacity.
If the archive becomes very large, split sitemap output and monitor build time;
the source-of-truth and static-serving model can remain unchanged.
